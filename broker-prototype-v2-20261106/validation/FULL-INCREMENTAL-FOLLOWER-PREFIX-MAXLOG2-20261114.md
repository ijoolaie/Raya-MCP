# Full Incremental Model — Follower Prefix Agreement, MaxLog 2 — 2026-11-14

## Purpose
Extend the full multi-node bounded check from MaxLog=1 to MaxLog=2 and include a two-term run. The test checks both that matchIndex is within the follower's current log length and that the leader/follower log prefixes are identical through matchIndex.

## Test module and invariants
Test-only derived module: `WitnessV2AppendEntriesIncrementalFollowerPrefixCheck.tla`

The original transition relation is copied from `WitnessV2AppendEntriesIncremental.tla`; only the test module name and two invariants are added:
- `LeaderMatchWithinFollowerLog`: matchIndex <= Len(follower log).
- `LeaderMatchPrefixAgreement`: leader and follower log sequences are equal through matchIndex.

Both invariants are checked alongside TypeOK, CommitIndexBound, NextIndexBound, MatchIndexBound, and CommittedPrefixAgreement.

## Interpretation and limitations
The full incremental transition relation preserves the two checked matchIndex/prefix relationships in these finite state spaces. The stronger sequence-equality check is materially more informative than checking log length alone.

This remains bounded evidence. MaxLog=2 and MaxRequestId=1 do not cover arbitrary log lengths or multiple outstanding request identifiers. The model uses abstract leadership assumptions and does not establish crash durability, a full election protocol, full Raft correctness, or Production readiness. The run does not justify changing the base model.
